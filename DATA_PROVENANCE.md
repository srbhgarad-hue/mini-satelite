## 1. Executive Summary & Provenance Mandate

Space Netra is a geospatial satellite change intelligence platform designed to monitor municipal urban expansion, industrial growth, and structural alteration across Chhatrapati Sambhajinagar.

During development, multiple data streams coexisted in the codebase:
1. **Authentic optical aerial/satellite photography** captured across historical epochs (2016, 2020) and current basemaps (2025/2026).
2. **Procedural synthetic fallbacks** generated by drawing routines when tile servers were unreachable offline.
3. **Calibrated synthetic multispectral rasters** generated with statistical reflectance distributions to benchmark band math and cloud masking.
4. **Authentic STAC satellite catalogue metadata** referencing real Copernicus Sentinel-2 Level-2A granules.
5. **Semantic search vector embeddings** indexing remote-sensing benchmark scene patches.
6. **An experimental deep-learning change-detection model** trained on the S2Looking benchmark dataset.

**Core Integrity Rule:**  
Under no circumstances may synthetic test fixtures, procedural drawings, or experimental AI predictions be presented to users, municipal planners, or downstream algorithms as genuine, physically observed satellite measurements.

## 3. Disentangling Metadata from Pixel Provenance

A critical flaw identified during the audit was the conflation of **catalogue metadata** with **raster pixel values**:

* In `download_satellite_data.py`, `query_stac_for_anniversary_scenes()` executed genuine STAC queries against Microsoft Planetary Computer, returning real Copernicus product identifiers:
  * T1: `S2A_MSIL2A_20210330T052641_R105_T43QEB_20210330T192519`
  * T2: `S2A_MSIL2A_20240314T052641_R105_T43QEB_20240314T103346`
* However, the subsequent function `synthesize_calibrated_rasters()` generated pixel values using `np.random.normal()` and wrote them directly to `data/change_detection/source/` under genuine-sounding filenames (`t1_b04.tif`, `t2_b08.tif`).
* The manifest `provenance_manifest.json` recorded genuine Copernicus scene metadata alongside these synthetic arrays, creating the illusion that the pixels were genuine physical surface reflectance measurements.

### Corrective Action Taken:
1. **Physical Quarantine:** All synthetic band arrays and previews have been permanently moved out of `data/change_detection/source/` into `data/synthetic_test_fixtures/`.
2. **Manifest Schema Correction:** `provenance_manifest.json` now explicitly includes a `provenance_classification` block:
   ```json
   "provenance_classification": {
     "pixel_provenance": "SYNTHETIC_SIMULATED_RASTER",
     "metadata_provenance": "VERIFIED_COPERNICUS_STAC_METADATA",
     "is_synthetic": true,
     "provenance_warning": "CRITICAL DATA INTEGRITY NOTICE: Scene IDs represent genuine Sentinel-2 Level-2A products, but raster pixel values are synthetic benchmark arrays..."
   }
   ```
3. **Decoupled Architecture in `download_satellite_data.py`:**
   * **Operation 1:** `query_stac_for_anniversary_scenes()` — STAC catalog discovery.
   * **Operation 2:** `download_real_sentinel2_rasters()` — Explicitly documented as *Not Yet Operational* (requires SAS-token authenticated Azure blob streaming and GDAL/rasterio).
   * **Operation 3:** `synthesize_calibrated_rasters()` — Quarantined to `data/synthetic_test_fixtures/` with explicit synthetic notices.

## 4. Preventing Silent Synthetic Fallbacks in the Photographic Pipeline

In earlier versions of `photo_streamer.py`, when an HTTP tile request failed (e.g., offline or network timeout), the function `generate_photorealistic_fallback()` was called automatically. It drew a procedural image (asphalt road corridor at y=118..124 with road stripe at y=127 and rectangular boxes) and saved it directly to `data/change_detection/source/csn_<hash>_<epoch>.jpg`. Subsequent executions saw the cached file and treated it as authentic satellite imagery.

### Corrective Action Taken:
1. **Procedural Signature Detection (`is_procedural_synthetic`):**
   ```python
   def is_procedural_synthetic(image_input):
       # Checks for synthetic fixture directory, synth_demo_ prefix,
       # and procedural pixel signature (road corridor std dev < 10.0, road stripe mean > 180)
   ```
2. **Purge of Live Cache:**
   All procedural synthetic drawings (`csn_767ce0d3_*`) have been removed from `data/change_detection/source/`. The 9 synthetic drawings are quarantined in `data/synthetic_test_fixtures/` with explicit `synth_demo_` prefixes.
3. **Strict Fallback Policy:**
   * In live production mode (`allow_synthetic_demo=False`, the default), a failed remote acquisition **NEVER** generates or loads synthetic drawings. It returns `status="ACQUISITION_FAILED"`, `is_real=False`, and a detailed error message.
   * Only when `allow_synthetic_demo=True` is explicitly requested (e.g. by checking the UI toggle in sidebar or in test scripts) does it generate fixtures, and those fixtures are saved exclusively to `data/synthetic_test_fixtures/synth_demo_*`.

## 6. Safe Transition & Reclassification Criteria

To upgrade an asset from `SYNTHETIC` or `UNKNOWN` to `VERIFIED_REAL`, the following technical evidence is required:

1. **For Sentinel-2 Multispectral Rasters:**
   * Ingest raw Level-2A SAFE or Cloud-Optimized GeoTIFF (COG) files directly from Copernicus Data Space Ecosystem (CDSE) or Microsoft Planetary Computer.
   * Verify SHA-256 checksums against the official Copernicus catalog.
   * Retain intact GeoTIFF georeferencing metadata (TIFFTAG_GEOKEYDIRECTORYTAG) with EPSG:32643 projection.
   * Store raw downloaded bands in `data/change_detection/source/` with manifest recording the ingestion pipeline run ID.
2. **For High-Resolution Optical Tiles:**
   * Verify HTTP response from Wayback MapServer WMTS with HTTP 200 and Content-Length > 5000 bytes.
   * Record Wayback release ID (e.g. `WB_2016_R02`), tile matrix coordinates (`x`, `y`, `z`), and capture date in cache headers.
   * Confirm pixel entropy and absence of procedural drawing artifacts.
3. **For Machine Learning Models:**
   * Train on verified local bitemporal pairs covering Chhatrapati Sambhajinagar with ground-truth municipal building permits.
   * Document validation IoU, F1 score, precision, and recall on an independent local holdout set.

## 7. Real Satellite Pyramid Resolution (Minimizing Synthetic Reliance)

To ensure that human operators can compare real satellite photography rather than uninformative procedural drawings:

1. **Native Tile Availability:**
   * **Current (2025/2026):** Native high-resolution optical basemaps are available across Zoom 15, 16, 17, and 18.
   * **Mid-Stage (2020 Wayback):** Native tiles are available across Zoom 15, 16, 17, and 18.
   * **Historical (2016 Wayback):** Native tiles are fully complete across Zoom 15 and 16. Zoom 18 returns HTTP 404 on the Esri Wayback MapServer.
2. **Pyramid Resolution Strategy:**
   * When a high zoom level (Zoom 17 or 18) is requested for an epoch that lacks native tiles, `photo_streamer.py:fetch_real_tile_with_pyramid_fallback` fetches the verified native parent tile (Zoom 16), calculates the sub-quadrant coordinates matching the target tile bounds, crops the exact geographical window, and resamples to 256×256 using Lanczos interpolation.
   * **Result:** All 7 municipal growth sectors across Chhatrapati Sambhajinagar display authentic, high-resolution optical satellite photography across all 3 historical epochs at all zoom levels (15 to 18).
   * Procedural synthetic drawings are completely bypassed in standard operation.
